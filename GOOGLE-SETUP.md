# Google-вход и доступ к закрытому API

Windows-клиент использует системный браузер, Authorization Code + PKCE, `state`, `nonce` и временный callback на loopback-адресе. Нужен OAuth-клиент Google типа **Desktop app**. Сам редактор работает из EXE; браузер используется только для авторизации.

## Текущая конфигурация

API размещается на Cloudflare через Sites и сохраняет закрытый доступ. Клиент проходит два независимых уровня проверки:

1. Служебный доступ к закрытому Sites API, отдельно настроенный владельцем для этого ПК.
2. Google-сессия, по которой API проверяет аккаунт и владельца проекта.

Переменная сервера `GOOGLE_ALLOWED_EMAIL` ограничивает доступ Google-аккаунтом владельца. Она проверяется при входе и при использовании существующих сессий. Служебный доступ сам по себе не даёт права читать проекты без действующей Google-сессии.

## Настройка собственного сервера

1. Создайте собственный проект в Google Auth Platform и OAuth-клиент типа **Desktop app**. Если проект находится в режиме тестирования, добавьте разрешённый аккаунт в тестовые пользователи.
2. В настройках среды своего Sites проекта укажите `GOOGLE_DESKTOP_CLIENT_ID`. Если Google выдал client secret, сохраните его только как серверный секрет `GOOGLE_DESKTOP_CLIENT_SECRET`.
3. Задайте `GOOGLE_ALLOWED_EMAIL` для разрешённого аккаунта. Не удаляйте это ограничение при переносе конфигурации: отсутствие значения расширяет круг допускаемых Google-аккаунтов.
4. Сохраните закрытую политику доступа Sites. Настройте D1/R2, примените миграции и опубликуйте сервер через инструменты Sites.
5. Укажите адрес своего API в `desktop/DesktopApp.cs`, затем соберите интерфейс и EXE по [CONTRIBUTING.md](CONTRIBUTING.md).
6. Отдельно настройте служебный доступ для нужного пользователя Windows, как описано ниже, и проверьте реальный Google-вход.

## Настройка доступа на другом ПК

Эту операцию выполняет владелец или уполномоченный администратор Sites. Он получает служебные учётные данные закрытого API через поддерживаемые инструменты хостинга и сохраняет их на целевом ПК, зашифровав Windows DPAPI с областью `CurrentUser`, в `%LOCALAPPDATA%\PixelStudio\service-access.bin`.

Ключ не должен попадать в исходники, EXE, JavaScript, файлы конфигурации репозитория, журналы или общий архив. Уже созданный `service-access.bin` нельзя использовать как переносимый ключ для другого пользователя Windows: настройку выполняют заново в его контексте. При недоступности или отзыве служебных данных облако не работает, а локальные инструменты и файлы остаются доступны.

Для самостоятельной копии проекта нужны собственный Sites API, свой Google OAuth-клиент и отдельная настройка доступа. Публикация исходников не предоставляет доступ к сервису владельца.

## Проверка входа

В приложении нажмите **«Войти → Войти через Google»**, выберите разрешённый аккаунт и вернитесь в окно Pixel Studio. Проверьте сохранение и повторное открытие облачного проекта. Сеанс действует до 30 дней; выход отзывает его на сервере.

Приложение запрашивает `openid email profile`. Пароль Google и access/refresh tokens не сохраняются. Сервер проверяет подпись ID token, издателя, аудиторию, срок действия и nonce. Идентификатор аккаунта строится по `sub`; электронная почта используется для ограничения доступа и отображения.
