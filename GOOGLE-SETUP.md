# Google-вход на любом ПК

Pixel Studio 0.2.1 использует системный браузер, Authorization Code + PKCE, одноразовые state/nonce и временный callback на 127.0.0.1. Нужен Google OAuth-клиент типа **Desktop app**. Сам редактор работает из EXE.

## Текущая конфигурация

Адрес API доступен из интернета. Проекты требуют Google-сеанса: каждый пользователь видит только свои записи и изображения. Анонимное чтение и запись запрещены; ID чужого проекта не даёт доступа. Служебный файл service-access.bin на новом ПК больше не нужен и не читается клиентом 0.2.1.

Серверные настройки:

- GOOGLE_DESKTOP_CLIENT_ID — публичный ID OAuth-клиента.
- GOOGLE_DESKTOP_CLIENT_SECRET — если выдан Google, только секрет среды сервера.
- GOOGLE_ALLOWED_EMAIL — необязательное ограничение для частного развёртывания. В текущем сервисе оно удалено по выбору владельца, поэтому разрешён любой подтверждённый Google-пользователь.

Запрашиваются только openid, email и profile. Пароль вводится на странице Google, не в редакторе. Gmail, Drive и управление аккаунтом приложению не нужны. Google-токены не сохраняются в базе; приложение создаёт собственный сеанс, хранит его хеш на сервере и шифрованную cookie на ПК. Подробнее: [PRIVACY.md](PRIVACY.md).

## Собственный сервер

1. Создайте свой проект Google Auth Platform, настройте имя и контакт приложения и создайте OAuth-клиент Desktop app.
2. Настройте свои D1/R2 и примените SQL-миграции из drizzle/.
3. Укажите OAuth ID и секрет в среде своего Sites API. Для входа с обычного EXE адрес API должен быть доступен без отдельной платформенной страницы входа; проектные данные при этом должны оставаться за серверной Google-авторизацией.
4. Для всех Google-аккаунтов не задавайте GOOGLE_ALLOWED_EMAIL; для частного сервиса задайте нужную почту. Смена ограничения проверяется и для уже выданных сеансов.
5. Укажите свой URL в desktop/DesktopApp.cs и соберите клиент по CONTRIBUTING.md. Не включайте секреты в EXE, JavaScript, исходники, архивы или журналы.
6. Проверьте вход, сохранение/повторное открытие проекта, выход, запросы без cookie и изоляцию двух аккаунтов.

Для одних лишь базовых областей openid/email/profile Google допускает вход пользователей вне списка тестеров даже в статусе Testing. Для дополнительных областей и брендинга действуют отдельные требования Google; не запрашивайте лишние разрешения. Официальное описание: https://developers.google.com/identity/protocols/oauth2/production-readiness/overview .

## На другом ПК

Скачайте версию не ниже 0.2.1, распакуйте Windows-архив, запустите Pixel Studio.exe и нажмите «Войти через Google». Копировать ключи или cookie между компьютерами не требуется. Каждый ПК создаёт свой сеанс. Версия 0.2.0 с сообщением CLOUD_ACCESS_MISSING требует однократного ручного обновления.

Если Google показывает ошибку своей страницы входа, сохраните её код без токенов и приватных данных: блокировка OAuth, неверный тип клиента и сетевой сбой отличаются от ошибки сервиса редактора.
